# 1.8.2：面板中重新开始计时

日期：2026-11-20。基线：1.8.1（ebcfda4），修改前和发布前均核对 origin/main，没有上游新增提交。

## 原因与修复

过程模式下，DAT 视图是控制面，`obsidianBinding.getActivePath()` 返回 null，同时保留计时状态中已绑定的文档。丢弃本轮后，`TimerService.startCurrent()` 只查询当前阅读目标，因 null 提前退出，按钮没有反馈。

开始入口现在只在自己的面板聚焦且非并行模式时使用已绑定目标。新一轮复用现有暂停机制，先暂停并标记等待内容聚焦；回到同一文档后恢复。其它视图仍使用当前实际目标，不猜测最近文档。没有新增类、计时状态或存储格式。

自动面板暂停与重新开始共用 `pauseForTool()`，在状态通知前设置暂停来源。UI 通过 `isWaitingForFocus()` 展示中英双语提示，并将等待状态加入结构签名；恢复或结束后提示消失。普通可见文字使用已有卡片样式，没有增加 DOM 查询或 CSS 覆盖。

测试注意：脚本调用按钮的 `.click()` 不会替代真实鼠标对工作区叶子的聚焦。复现面板行为时先用工作区 API 明确激活 DAT 叶子，避免用仍聚焦文档的状态误判暂停逻辑。
